## Closure and reachable inputs

The [upload lockfile](https://github.com/actions/upload-artifact/blob/043fb46d1a93c77aae656e7c1c64a875d1fc6a0a/package-lock.json) contains artifact 6.2.0, Azure storage-blob 12.31.0/core-xml 1.5.0, fast-xml-parser 5.4.1, and undici 6.23.0. The [download lockfile](https://github.com/actions/download-artifact/blob/3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c/package-lock.json) contains artifact 6.2.1, storage-blob 12.30.0/core-xml 1.5.0, fast-xml-parser 5.3.4, minimatch 10.1.1, and undici 6.23.0. The [attest implementation lockfile](https://github.com/actions/attest/blob/508db95dd578ae2727ebd6217d5ba78e4fbda05d/package-lock.json) includes undici 8.9.0 and nested 6.25.0. Lockfile presence alone does not establish that an API is invoked.

**XML:** Upload's [`uploadToBlobStorage`](https://unpkg.com/@actions/artifact@6.2.0/lib/internal/upload/blob-upload.js) invokes `BlockBlobClient.uploadStream`. The Azure client response pipeline reaches [`deserializeResponseBody` → `parse`](https://unpkg.com/@azure/core-client@1.10.1/dist/commonjs/deserializationPolicy.js) for a non-streamed response with a body and XML content type, including an Azure error response. That calls [`@azure/core-xml.parseXML` → `XMLParser.parse`](https://unpkg.com/@azure/core-xml@1.5.0/dist/commonjs/xml.js), with entity processing enabled. The parser input is the **Azure HTTPS response body**, not uploaded archive bytes. [Entity expansion](https://github.com/advisories/GHSA-8gc5-j5rx-235r) remains relevant to a malicious service response; trusted service endpoints bound that risk. Upload's XML serialization uses SDK-generated block identifiers, not user-controlled XML. Download's [HTTP streaming implementation](https://unpkg.com/@actions/artifact@6.2.1/lib/internal/download/download-artifact.js) uses the Actions HTTP client and archive stream; its bundled Azure XML parser is uncalled on this download path. This includes the download closure's [critical entity-name advisory](https://github.com/advisories/GHSA-m7jm-9gc2-mpf2).

**Patterns:** The [download implementation](https://github.com/actions/download-artifact/blob/3e5f45b2cfb9172054b4087a40e8e0b5a5461e7c/src/download-artifact.ts) takes the exact-name branch before the `Minimatch` pattern branch. All eight workflow downloads specify literal names and omit pattern, cross-run selectors, and cross-repository tokens. [Minimatch backtracking](https://github.com/advisories/GHSA-23c5-xmqv-rm74) and [brace expansion resource exhaustion](https://github.com/advisories/GHSA-rgw5-rvv9-x895) receive no attacker-selected patterns: upload paths and attestation subjects are a finite, workflow-owned list. The closure's lodash [template injection](https://github.com/advisories/GHSA-r5fr-rjxr-66jc) and [path mutation](https://github.com/advisories/GHSA-f23m-r3pf-42rh) APIs are not used by the release helpers; no untrusted template, property path, or XML-builder input is supplied by this workflow.

**HTTP:** Undici advisories include [WebSocket parsing](https://github.com/advisories/GHSA-f269-vfmq-vjvj), [Blob-like MIME injection](https://github.com/advisories/GHSA-m8rv-5g2x-5cg5), and [HTTP framing](https://github.com/advisories/GHSA-2mjp-6q6p-2qxm). The workflow uses GitHub/Actions, Azure artifact storage, and GitHub/Sigstore attestation services over HTTPS, without user-selected endpoints, WebSockets, Blob-like MIME APIs, cookie construction, or registry pushes. Service-generated URLs and responses remain a trust boundary; this is not protection against a compromised service or pinned action. npm's advisory endpoint returned upload/download closure findings on the review date; the attestation closure query failed with a transport error, so no fresh clean-audit claim is made for it.

## Final YAML review boundary

The final YAML was parsed and checked for the protected-main trigger, immutable SHA checkouts, four native targets, explicit digest errors, exact same-run downloads, fixed uploads, dependency ordering, and separate read-only build / attestation / publication permissions. All checkouts disable credential persistence. Privileged jobs invoke only checked-out validation code and trusted actions/CLI tools; downloaded archive members are never extracted or executed. Publication verifies remote asset digests before exposing the draft. Zizmor 1.28.0's offline scan reported no findings; no suppression was added. This local self-review and independent static analyzer do not constitute a separate human or agent security review. Hosted execution and independent review remain validation limits.
